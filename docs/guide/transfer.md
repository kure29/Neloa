# 发送与接收文件

## 发送

1. 在设备页选中一台**已配对**的设备。选中的设备会有一个勾选标记；再次点击该设备或勾选可以取消，桌面端也可以点击设备区域的空白处取消。
2. 点击「选择文件」，或者把文件直接拖进窗口（macOS 与 Windows 支持多文件拖入）。
3. 待发送列表会列出每个文件的名称与大小，可以逐个移除。
4. 点击发送。

发送按钮上方那一行说明会告诉你当前这一步的实际结果，比如"将向 Surface Laptop 发送 24.6 MB，端到端加密"。按钮处于不可用状态时，同一行会说明原因。

## 接收

接收端不会自动保存任何东西。每收到一个文件，都会弹出一个确认页，显示：

- 发送方设备名称
- 文件名与大小
- SHA-256 校验状态；兼容旧客户端时也会显示发送前摘要

只有你选择「接受并保存」，传输才会开始。选择「拒绝」会直接结束这次传输并通知发送方。

## 文件去了哪里

接收的文件先写入一个临时文件，**校验通过之后**才会发布到系统下载目录的 `Neloa` 文件夹。发布时不会覆盖同名文件——已存在同名文件时会另起一个名字。

如果传输中断、被取消或被拒绝，对应的临时文件会被删除，不会在磁盘上留下半个文件。

## 队列、取消与重试

- 可以一次性选择多个文件，它们会进入发送队列。
- 进行中的传输会显示在浮动的传输面板里，包含方向、阶段、百分比、已传输字节与当前速度。
- 每个传输都可以单独取消。
- 发送失败或被中断的文件，会在[传输记录](/guide/transfer#传输记录)里保留「重试」按钮。

传输阶段会明确显示当前在做哪件事：等待对方接受、加密发送中、接收并解密、校验并写入。与不支持流式校验的旧客户端互传时，还会先显示「计算校验值」。

## 完整性校验

新版本之间传输时，发送方会在读取文件并加密发送的同时计算 SHA-256，在经过认证的完成消息中提交摘要；接收方同步计算自己的摘要，两者一致才会发布最终文件。这样不会为了预先计算摘要而把源文件完整读取两遍。与旧客户端互传时，会自动使用发送前预哈希的兼容流程。

这意味着：**你看到的"已完成"，是校验通过之后的完成**。

## 传输记录

记录页保存最近的传输结果，包含方向、文件名、对端设备、大小、时间与状态（已完成 / 失败 / 已取消 / 被拒绝）。纯文本剪贴板事件也会记录在这里，但只保留对端、方向、字节数与时间——正文不会写入记录。
