# 故障排查

先看「设置 → 连接」最上方那条总结。它会给出「连接正常」或「N 项需要处理」，并把需要注意的项目直接列出来，每一项都带一句处理建议。

## 连接状态

展开「设置 → 连接 → 连接状态」，可以看到六个检查项：

| 检查项 | 关注什么 |
| --- | --- |
| 局域网连接 | 本机网络接口与 QUIC 监听是否就绪 |
| 附近设备发现 | mDNS/Bonjour 是否在正常工作 |
| 设备身份保护 | 长期设备密钥能否从系统凭据库读取 |
| 客户端版本 | 当前版本与协议能力 |
| 剪贴板同步 | 是否开启、是否处于可用状态 |
| 自建中继 | 是否启用、是否已连接 |

## 找不到设备

1. 确认两台设备在同一个网络，并且都打开着 Neloa。
2. 看设备页的提示行是「正在查找附近和中继设备」还是「设备发现暂不可用」。后者说明本机的发现服务没起来，看「连接状态」里的「附近设备发现」。
3. Windows 上检查防火墙是否允许 Neloa 使用专用/公用网络。
4. iOS 首次运行会请求「本地网络」权限；拒绝之后需要在系统设置里重新打开。
5. Android 需要 Wi-Fi 可用；Neloa 在应用存活期间持有 mDNS 多播锁，但切换到只走蜂窝网络时局域网发现自然不会有效。

## 设备显示「版本不兼容」

两台设备的协议范围没有交集，或对方缺少本次操作需要的能力。升级对方的 Neloa 即可。旧版本会被当作协议 0 处理，并收到明确的提示，而不是进入配对或传输流程。

## 传输失败或卡住

- 在传输面板里取消后重新发送。
- 发送失败的记录可以在记录页点「重试」。
- 大文件失败时先确认两端都没有进入休眠，并且网络没有在传输中途切换。
- 如果对方一直停在"等待对方接受"，说明接收端还没有确认那个文件——接收端不会自动保存。

## 中继连不上

- 确认地址以 `wss://` 开头，且末尾是 `/v1/ws`。
- 确认两端的令牌完全一致。
- 确认反向代理把 HTTPS 正确转发到 `127.0.0.1:8787`，证书有效。
- 看「连接状态 → 自建中继」；即使中继失败，局域网直连仍然可用。

## 剪贴板没有同步

- 确认开关是打开的，并且开关下方的最近事件有记录。
- 超过 8 KB 或命中敏感内容标记的文本**按设计不会发送**。
- 移动端只在应用处于前台时同步。
- 刚开启时已存在于剪贴板里的内容不会被发送，只有之后新复制的内容才会。
